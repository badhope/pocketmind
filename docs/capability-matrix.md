## 为什么模拟器不能验证手机能力

不是配置问题，是**物理缺失**：

- 没有 SIM 卡 → `termux-sms-list` 返回空数组，`termux-telephony-call` 直接失败
- 没有 GPS → `termux-location` 只能拿到模拟坐标或超时
- 没有真实传感器 → `termux-sensor` 返回的是模拟器注入的假数据
- 电池是模拟的 → `termux-battery-status` 永远返回 100% / CHARGING

所以：**模拟器能验证「程序逻辑对不对」，不能验证「硬件能力通不通」。**
这也是为什么本项目用三种环境分工：

```
容器       → 业务逻辑、单元测试、回归（主战场）
模拟器     → 安装脚本、依赖可装性、启动链路
真机       → 硬件能力、aarch64 编译、电源管理
```

## 联网搜索的隐私边界

这是「数据不出本机」的产品，但**联网搜索会外发**：

- 查询词会发送到第三方搜索引擎（Bing / DuckDuckGo）
- 因此输入框的「联网」开关**默认关闭**，必须手动开启
- 开启后每次搜索都会在审批层面告知（`web_search` 是 `write` 级工具）

如果你完全不想外发：不开启联网开关即可，本机知识库（`kb_search`）与文件工具在离线时完全可用。

## 已知的「有条件可用」

| 情形 | 表现 | 怎么办 |
|---|---|---|
| 设备无 tzdata（部分 Android） | 定时任务按 UTC 解释 | 设置 `TZ=Asia/Shanghai` 环境变量 |
| 外网不通 | 联网搜索、云端模型不可用 | 用局域网自建模型（Ollama / vLLM），或纯离线使用知识库 |
| 未装 termux-api | 25 个手机工具全部返回「未安装」 | `pkg install termux-api` + 安装 Termux:API App |
| 电池优化未关 | 锁屏后进程被系统杀死 | 系统设置里给 Termux 关闭电池优化；`start.sh` 已申请 wake-lock |
| 只装了 python3 没装 python | 启动脚本找不到解释器 | 已修：`boot.sh`/`start.sh` 自动探测 python/python3 |
